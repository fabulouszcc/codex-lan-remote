# 小米 14 Ultra 首次测试

当前为 0.2 ARM64 开发预览 APK。用户已反馈 0.1 手机连接成功；0.2 的新界面、缓存和通知仍需真机确认。电脑 HTTPS 到桌面测试聊天的闭环已通过。

## 已提供的内容

- APK：`.local/releases/codex-lan-0.2.0-preview.apk`，Android 9+，面向小米 14 Ultra 的 ARM64 架构。与 0.1 使用同一签名，可覆盖安装保留配对及 ET 配置。
- 内置 EasyTier：网络名称、密钥、手机静态虚拟 IPv4/前缀、peer 地址表单；加密保存；系统 VPN 授权；前台连接通知和断开入口。
- 聊天：可选择电脑本地列表中的聊天，主动加载历史；每台电脑分别加密缓存最多 24 个聊天、每个最近 50 轮，离线只读。发送任务、执行中追加、打断对话、命令/文件审批。桌面尚未加载的聊天先显示持久化历史，桌面打开后重新接入实时控制。
- 通知：独立前台服务维持后台同步，任务完成/失败和待审批分渠道通知。简单审批可在通知选择，复杂或截断详情进入 App；离线撤销审批按钮，电脑复核请求及轮次。通知仅覆盖已经打开并订阅的聊天。
- 不包含：可安装 Codex 插件包、多设备列表、自动发现、消息队列 UI、附件、完整 Markdown 渲染。停止底层项目进程仍未实现。

## 手机操作

1. 将 APK 传到手机并安装，打开 **Codex LAN**。
2. 点击 **内置 EasyTier · 配置与连接**，填写你自己的网络名称、密钥、预期虚拟子网地址（含前缀，如电脑 `10.90.0.1/24`），开启 DHCP 自动分配手机地址，并填写底层 peer 地址（如 `tcp://服务器地址:11010`，每行一个）。示例地址不是实际组网参数。
3. 手机虚拟 IP 不得与电脑或其他节点重复。peer 应填写可达的底层服务器地址，不能填写本虚拟子网内的节点地址。
4. 点击保存并连接，按系统提示授予通知和 VPN 权限。Android 同一用户只能有一个活动 VPN，启动时可能替换其他 VPN；按实际系统提示选择。
5. 重新打开 EasyTier 设置查看虚拟接口与路由节点数量。接口建立只代表 TUN 已建立，仍要用电脑连接测试确认通路。
6. 从电脑 `.local/phone-pairing.local.json` 取得配对信息。可将完整 JSON 通过可信方式复制到手机，点击 **粘贴电脑配对信息**，也可分别填写地址、证书指纹与配对码。
7. 点击配对并连接。默认从专用测试聊天开始；使用“切换聊天”浏览电脑列表。当前开发机已显式启用 `allowSelectedChats`，手机选择后可控制桌面已加载的聊天；不具备实时持有者的聊天只显示历史。
8. 升级后先允许通知，在“通知与后台同步设置”中检查各渠道。任务开始后返回桌面等待提醒。若 HyperOS 限制后台运行，在系统应用设置中调整本应用的后台运行/省电设置；前台服务不代表系统强制终止后仍能通知。

内置 ET 首版仅路由所配置的虚拟子网，不转发其他代理子网、不接管默认互联网路由。密钥不需要发给助手。配对信息与 EasyTier 组网密钥是两套不同凭据，不能互相代用。

## 电脑操作

本机配置：`.local/gateway.local.json`。`host` 是这台电脑已有的局域网或虚拟网卡 IP，`port` 是远控服务端口；不是组网中继服务器地址。`threads` 只填写明确允许手机访问的聊天。

可选 `codexBinary` 指向当前桌面自带的 Codex 可执行文件，用于独立只读历史查询，绝不调用 resume、start 或审批。`allowSelectedChats` 默认为 false；设为 true 后，已配对手机可以从本机聊天列表选择并授权控制该聊天。实时控制仍经现有桌面持有者，不使用历史查询进程冒充桌面运行实例。

```json
{
  "host": "电脑本机虚拟IP",
  "port": 9443,
  "name": "我的电脑",
  "threads": [{ "id": "明确授权的桌面聊天ID", "name": "聊天名称" }]
}
```

```powershell
npm run start:gateway
```

控制台启动后生成新的 `.local/phone-pairing.local.json`；配对码 10 分钟有效，已配对手机的令牌继续有效。过期则停止本连接服务并重新启动，证书身份和已配对记录保留。不要向他人公开该 JSON。

服务只允许绑定本机具体地址，不默认监听所有网卡。连接超时需检查手机与电脑的 ET 参数、虚拟网段、电脑连接服务和防火墙；本次没有修改 Windows 防火墙，也没有改动现有 EasyTier 服务。

撤销所有手机授权：先停止本连接服务，移除 `.local/secrets/devices.local.json`，再启动。手机上的“清除本机配对”只清除手机凭据。`.local/secrets` 含本机私钥和身份配置，不能提交或分享。

## 构建与验证

```powershell
./scripts/prepare-easytier.ps1
./scripts/build-android.ps1
npm test
node scripts/verify-gateway.mjs --allow-test-turn
```

构建脚本默认使用本机 `.local/toolchain` 下已准备的 JDK 17、Gradle 8.9 和 Android SDK 35，可通过参数指定其他工具路径。Android 调试签名、构建缓存和 APK 都保存在 `.local`。`npm test` 的 TLS 用例需要 JDK keytool，可通过 `CODEX_LAN_TEST_KEYTOOL` 指定；默认使用本机 Android Studio 的 JBR。

最后一条验证命令需要先设置 CODEX_LAN_TEST_THREAD，只会向该明确授权的专用测试聊天发送一条实际任务，产生模型调用；不会向其他聊天写入。报告在 `.local/verification/gateway-e2e.local.json`，不包含配对密钥或完整聊天正文。

EasyTier 二进制的固定来源、校验值和当前限制见 [实现核查](Moonlight内置EasyTier参考.md)。正式发布前仍需补齐对应原生源码的可复现构建。

## 真机待验收

- 首次启动、通知和 VPN 权限，拒绝权限后的恢复。
- 原生库加载、加入实际组网、虚拟 IP 冲突、断开和重连。
- 手机发送后桌面同一聊天可见；两端处理审批后另一端立即失效。
- 返回桌面、锁屏、网络切换、HyperOS 省电与进程被终止后的表现。
- 窄路由不影响手机访问其他网络，已有 VPN 替换提示符合预期。

0.2 的聊天同步和通知由独立 SessionService 负责，不随 Activity 退到后台而停止；EasyTier VPN 另有独立服务。首次同步不补发旧任务的完成通知，当前待处理审批会提示。通知“停止同步”仅停止聊天同步，重新打开 App 会恢复；不会停止 Windows 项目命令或 EasyTier VPN。
