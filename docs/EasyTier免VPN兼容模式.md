# EasyTier 兼容其他 VPN

对应 #2。已有连接方式保持默认行为；在手机“设置 → EasyTier 组网”先断开，再开启“兼容其他 VPN”，保存并连接。网络名称、密钥、虚拟 IPv4、节点及电脑配对保持不变，无需新增公网中继或重新编译原生库。

启用后：复用现有前台组网服务，原生配置增加回环 socks5_proxy 与 no_tun/use_smoltcp；不请求 Android VPN 授权，不建立 TUN。仅本 App 对所配虚拟 IPv4 子网的 HTTPS 请求使用本地 SOCKS，其他目标保持原来的系统代理/网络选择。聊天、配对、用量和文件请求仍使用原证书指纹固定与请求取消。关闭此开关后恢复原 VpnService/TUN 路线。

所有启动入口（恢复、扫码配对、切换网络、设置连接）按模式决定是否请求 VPN；就绪判断不再依赖“虚拟接口”文字。连接模式保存在独立非敏感首选项，扫码导入不会覆盖它。停止时清除代理路由；免 TUN 模式下不因旧 VPN 绑定的 onRevoke 而误停本 App 的普通前台网络连接。

## 验证

- 固定捆绑 Android .so 的独立进程合成测试：parse/run 成功，回环 SOCKS5 握手成功、负 TUN FD 接受、仅自己的实例已清理；未连接外部节点，真实 App PID 与配对/网络首选项摘要前后不变。
- Android 上运行更新后的 RemoteApi，通过仅本地的 SOCKS/TLS 合成 fixture：正确指纹请求成功、错误指纹拒绝，未使用用户令牌。证明平台 HttpsURLConnection 的 SOCKS 路线与原固定证书逻辑可共存。
- Android 16 ARM64 实机通过 UI 开关切换后，显示免 VPN 虚拟地址和路由节点，真实跨节点 HTTPS 新认证持续返回。
- 用户明确确认另一 VPN 与手机连接同时正常；系统读取到 1 个由另一 UID 持有的活动 VPN 网络，本 App 同时有新认证请求。没有从普通前台组网服务抢占 VPN 槽位。
- JUnit 覆盖配置层级、保留加密、代理限于正确子网、无 DNS/伪造后缀匹配、无效端口拒绝和清除路由。未改配对/证书格式或上游包名/版本。

## 限制

当前实机证据来自 Android 16 和现有固定原生库；其他 Android 版本仍需覆盖。模式只提供本 App 到虚拟子网的连接，不能当作为手机其他应用提供完整组网路由。组网传输仍服从正在运行的 VPN 的网络策略；本地 SOCKS 只绑定 127.0.0.1。启动使用临时本地端口，如恰好被抢占会报告启动失败，可重试，绝不监听外部地址。
