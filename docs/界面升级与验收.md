# 手机与电脑设置入口升级

日期：2026-10-16。Android 0.3.0-preview（versionCode 7），电脑插件 0.3.1-preview。本次产物在本地构建、安装，尚未更新 GitHub Release。

## 手机端

- 聊天占据主屏，顶部为会话列表、当前会话与连接状态、设置入口。
- 会话抽屉支持名称搜索、当前会话标记、无结果提示；切换会话保留内存草稿，旋转保留草稿，重开恢复选中的会话。
- 底部圆角输入区集中发送操作；运行时可追加，停止按钮按任务状态显示。保留提交确认和重复请求保护。
- 用户消息采用右侧气泡，Codex 回复为通栏正文；支持基础加粗、行内代码、横向滚动代码块及复制。工具活动折叠显示，审批仍经明确详情确认。
- 独立设置页集中电脑、EasyTier、同步、通知和清除配对；组网运行状态自动刷新。
- 使用原应用 ID、原签名和原存储；不会清空配对、组网或历史缓存。

这是聊天体验与入口布局升级，没有宣称复刻官方客户端的全部功能。创建新聊天、附件、完整 Markdown 表格和相机扫码仍需另行实现。

## 电脑端

- 安装器在当前用户的桌面与开始菜单创建“手机连接设置”快捷方式。
- 快捷方式指向稳定的本机启动脚本，每次获取设置页凭据；不把访问令牌写进快捷方式。
- 旧版升级可更新本插件的 marketplace 来源，保留原配置、证书和设备授权。注册失败会尝试恢复旧来源。
- 设置页增加连接、配对、授权设备导航，以及再次打开设置的说明。

## 第二轮优化

Android 0.3.1-preview（versionCode 8），电脑插件 0.3.2-preview，已本地安装；GitHub 发布包仍为上述旧版本。

- 实时状态与历史读取共用顺序投影，逐项呈现用户消息、回复片段和工具卡片；补全同一轮内的多条用户消息。工具各自展开输入、输出与退出码，保留展开状态，并限制返回详情体积。
- 圆角输入区改为文字在上、连接方式与单个主按钮在下。运行且无草稿时显示停止，有草稿时显示追加；空闲且无草稿时禁用发送。
- 配对页、设置和输入区均提供连接方式入口，可分别保存局域网与 EasyTier 地址。切换前使用原设备授权及证书验证目标电脑，验证成功才保存。
- 电脑设置可选择本机私有网卡地址作为额外局域网监听；两个监听共用证书、配对会话和授权撤销，不管理已有系统 EasyTier 进程。

验证：33 项 Node 测试、16 项 Android 状态测试和 14 项已安装插件检查通过。真机经局域网直接连接，保留原配对；电脑发送的新消息、运行中追加的文字与回复均显示在手机上；工具在对应回复之后独立展开。实际输入及清空草稿验证了追加／停止切换，手机点击停止后，电脑实时回执为 interrupted。追加文字首次实测暴露了桌面 steeringUserMessage 类型遗漏；补上其 input 文本投影，并验证规范用户记录替换时不重复后，真机复测通过。临时延长的手机熄屏时间已恢复为原设置。

官方移动端资料查询在本次环境中不可用；布局按用户明确的交互要求优化，没有宣称与官方客户端逐像素一致。本轮没有重做通知及审批验收。

## 第三轮：合并工具与滑动性能

Android 0.3.2-preview（versionCode 9），已同签名覆盖安装，电脑插件沿用 0.3.2-preview。尚未上传新 GitHub Release。

- 每轮对话的工具调用汇总为一个默认折叠组，显示数量和运行／失败摘要；展开后可分别查看调用详情。用户消息和回复文字仍逐段显示。
- 网络连接方式放到顶部连接状态一行，点击打开局域网／EasyTier 选择；移除输入区内的网络入口。
- 聊天改为原生 ListView 回收视图，屏幕外的记录不再全部创建控件；后台准备显示数据，合并短时间同步更新，无变化时不刷新列表，滑动期间延后应用内容更新，保留阅读位置。
- 工具组及单条工具详情均按需创建，默认折叠时不生成命令输出控件。历史缓存原有数量限制保持不变。

18 项 Android 状态测试通过，新增每轮工具汇总、后续消息保留、稳定记录标识和长记录投影检查。真机验证合并组展开、顶部网络入口、聊天切换和历史滑动，无 AndroidRuntime 崩溃日志。原页面观察到约 6800 个视图，新页面在本次长聊天滑动中约 30～40 个视图；连续六次滑动采到 708 帧，系统计数卡顿 1 帧（0.14%），95 分位耗时 8ms。这是本次短时采样，不代表所有设备或场景；旧版同轮滑动未采到有效帧，不能计算公平的前后卡顿率差值。

## 第六轮：手机显示桌面输入消息

Android 0.3.5-preview（versionCode 12），电脑沿用 0.3.4-preview。本轮已覆盖安装到真机，尚未上传 GitHub Release。

对照桌面实时状态、HTTPS 投影及安卓合并／列表数据，用户消息数量一致，未发现服务端过滤输入文字。真机进一步复现了标题已切换、正文仍为旧聊天，滑动后才更新的问题：列表滑动状态可能没有收到 IDLE，导致后续记录一直被延后显示。另有连续同步时旧准备结果被一再丢弃、无法推进显示的竞争条件。

修复为：同一时刻只准备一份列表，完成的同聊天结果先显示，再处理最新快照；切换聊天时直接更新正文；滑动延后期间观察实际位置变化，停稳后自动应用记录，避免无限等待 IDLE。保留旧页面和旧聊天结果的隔离，维持列表回收及阅读位置。

22 项 Android 状态测试通过。真机验证原有桌面输入文字可定位显示；专用测试聊天中，从电脑发出的新消息和运行中追加文字均自动出现在屏幕上，无需手动滑动或同步。连续三次手动同步均未出现连接中断提示，甩动中切换聊天后标题与正文一致，无 AndroidRuntime 崩溃日志。测试后恢复原来的 1 分钟熄屏时间。

## 第五轮：大聊天实时接入与刷新误报

Android 与电脑插件 0.3.4-preview。修复真实桌面聊天快照超过旧 32 MiB 上限而断开共享实时通道的问题；适配器上限调整为 128 MiB，保留手机投影体积限制。增量状态改为沿路径复制，未变化的大工具内容不再重复复制，批次失败仍不修改旧快照。手机刷新、选中聊天和切换地址使用轮询代次识别过期请求，取消请求不再报告网络掉线，审批提交也不会被刷新取消。

## 第四轮：模型、定位和运行状态

Android 0.3.3-preview（versionCode 10）与电脑插件 0.3.3-preview 已安装；未更新 GitHub Release。

- 输入区左下角可选择模型与思考强度。模型来自已安装桌面二进制的只读 model/list，不硬编码账号可用列表；通过桌面现有聊天的 settings 接口应用，仅发送 model/effort 字段，读回确认后同步手机。对后续任务生效，不修改正在执行任务使用的模型。
- 对话右侧显示最近八条用户消息的编号、最早／最新入口，以及完整已加载记录定位抽屉。选择记录直接跳到原位置；问答传输标记在预览中转换成用户回答，定位仍指向原始记录。

- 活跃任务的状态显示在记录底部，随工具执行、等待处理或思考阶段更新。仅转发桌面提供的可见 summary；没有摘要时显示状态，不返回原始 reasoning content、加密内容或内部字段。离线及已结束任务不显示活动尾项。

验证：37 项 Node 测试、20 项 Android 状态测试、14 项已安装插件检查通过。专用测试聊天实际更换模型与思考强度，读取确认后恢复原设置；手机模型窗口加载成功，点击应用后电脑审计回执成功、读回与显示一致。真机验证右侧最早定位、抽屉选择目标消息、回复气泡及底部运行状态；列表保持视图回收。可见摘要提取及活动消失由状态测试覆盖，本次没有取得带可见摘要的真机样本，因此没有把状态显示称作完整思考内容同步。桌面升级后失效的旧二进制路径已在本机修复，安装器也会在旧路径不存在时刷新为已检测到的桌面二进制。

## 第十轮：修复新记录不在尾部与旧缓存顺序

Android 和电脑插件均升级为 0.3.9-preview（Android versionCode 16），已本机、真机覆盖安装，配对保留，未发布 GitHub Release。

复现本聊天桌面 canonical 记录为 51 轮、76 条用户输入，包含用户刚发送的新问题；历史接口返回最近 50 轮。旧合并逻辑先填历史 Map，再覆盖实时轮次，但覆盖不改变插入位置：仅实时流包含的早期轮次被追加到末尾。保留最后 50 轮时，旧轮次因此留在尾部；Android LinkedHashMap 合并又固化了这个错误顺序。侧栏 75 是当前载入的用户输入条数，并非总对话轮数或固定 75 条限制。

电脑合并时保留正文回退，再按桌面 canonical 顺序重新插入实时轮次，最后执行窗口限制；手机按服务返回顺序重新插入已缓存轮次，自动修复旧缓存，无需清除配对或本地历史。增加阅读历史时的“回到最新”按钮，侧栏预览明确标注“条提问”。

42 项 Node 测试、26 项 Android 测试及 14 项已安装插件检查通过。新增 51 轮实时与 50 轮持久历史交错、旧缓存顺序修复和正文保留的回归测试。真机已显示本轮用户新问题及后续助手回复，点击“回到最新”抵达当前活动尾项；随后新发布的助手进度无需额外点击即可同步显示。两个安装包及源码敏感信息检查通过；恢复原 1 分钟熄屏时间。

## 第十一轮：记录条末尾、ET 传输开销与切换清理

Android 与电脑插件升级为 0.4.0-preview（Android versionCode 17），已安装到本机和真机；未发布 GitHub Release。开机自启试验保持取消，没有合入本轮。

- 定位最后一条提问时，直接滚至最新回复／活动尾项；中间提问仍定位原位置。真机滑动到底后，活动尾项可见且“回到最新”按钮隐藏。
- 局域网与 ET 仍共用同一同步协议。手机独立的读请求复用所属连接的 TLS 上下文、socket factory 和 hostname verifier，保留证书固定校验与独立取消；目录刷新迁移到单独后台任务，不阻塞状态轮询或审批。Android 状态合并复制对象字段，避免每次反复序列化整段旧历史。
- 增加协商 gzip 与按会话基线的增量轮次。服务仅保存轮次摘要，发送变化内容及权威 turnOrder；手机保留未变正文、按权威顺序裁剪，基线或缓存缺失时重新获取全量。旧客户端保持全量兼容；授权撤销同时清除该会话基线。
- 切换局域网验证成功后，只关闭手机本 App 内置 ET。实测发现 Android 会继续绑定 VPN，普通 stopService 不一定触发 onDestroy；改为主动释放原生实例和 TUN 后撤销前台状态并 stopSelf。绑定对象保留时，允许再次连接时重新创建后台执行器；不涉及电脑外部 EasyTier 进程。

验证：43 项 Node 测试、27 项 Android JVM 测试与 14 项已安装插件检查通过。新测试覆盖 gzip 协商拒绝、增量内容和顺序、全量修复、撤销授权、丢失基线和缓存恢复。真机同局域网下用证书公钥固定的 HTTPS 小请求测得：ET 首次约 19ms、后续 3～4ms；局域网首次约 26ms、后续 3～4ms。仅为本次小样本，不代表所有路径或负载。真实双聊天全量约 1.55MB、gzip 约 441KB；同一会话无正文变化的增量约 2.4KB，不能把这个空闲结果当作所有活跃更新的大小。

诊断确认旧界面编辑内置 ET 并不等于启用，电脑当时运行已有网络，因模式未应用而拒绝 ET 码。另发现保存的内置虚拟地址是缺少前缀的裸 IPv4，TCP 11011 已占用。没有据此猜测并改写用户子网，也未停止占用端口的外部实例。电脑 CIDR 增加浏览器格式约束和明确提示，监听与管理端口移到可见区。尚未应用配置时生成按钮标明“保存启用并生成配对码”，服务端先校验手机 CIDR，再保存、启动、生成；无效手机地址不改变现有连接或轮换配对码。

25 项相关桌面／网关测试和 17 项安装检查通过。隔离页面显示 ET、以太网、两张 VMware 网卡；从局域网直接选择内置 ET、填写手机地址、点击配对按钮，模拟服务完成一次保存和启动，二维码 SVG 保持可见。已安装七个关键文件与源码一致，原已有网络连接恢复，真实配置和手机授权文件校验值不变。真实内置 ET 仍需用户补全正确前缀并选择独立空闲端口后启动；本轮未为测试修改真实参数。未发布 GitHub。

## 第二十二轮：管理员后台恢复与失联提示

现场页面显示 Failed to fetch，但仍保留旧“内置 ET 已启用”。检查确认管理端口无监听、manager 元数据和锁均已清理，内置 ET 进程也未运行。旧版没有保留启动失败记录，不能据此完整还原首次退出触发源。普通权限恢复后台后，内置 ET 很快退出，未建立连接服务。

电脑插件更新为 0.4.11-preview。管理员入口显式启动隐藏 daemon，等待其元数据就绪，再打开页面并在宿主中等待 daemon 生命周期，避免依赖短命 URL 打开器托管管理员后台。实际 Windows PowerShell 5.1 复测发现新脚本的 UTF-8 无 BOM 会出现中文解析错误，已统一发布包 PowerShell 文件为带 BOM 编码，并在每次打包时调用系统 Windows PowerShell 解析全部五个脚本。断线时页面改为“后台连接已中断／状态待确认”，不继续宣称旧连接已启用。自动启动失败写入有界事件，内置 ET 退出状态仅增加整数退出码和信号白名单，无原生日志或网络密钥。

15 项相关桌面测试通过，五个发布脚本在 Windows PowerShell 中解析零错误。通过系统 UAC 恢复管理员后台后，现场确认内置 ET 由插件管理、虚拟网卡建立、远控连接服务运行，真实配对信息导出接口成功；未轮换配对码或提交额外配对。管理员宿主保持运行，用户配置与手机授权文件校验值不变。用户之前要求停止的外部 easytier Windows 服务仍处于 Stopped，未重新开启。发布包与源码敏感信息扫描通过，未发布 GitHub。


## 第二十三轮：扫码 DHCP、配对生命周期与开屏动画

电脑插件与 Android 更新为 0.4.13-preview，Android versionCode 26。内置 ET 配对码默认携带 DHCP 模式和预期电脑子网，不指定手机静态 IP；电脑配对区移除必填手机地址。Android 等待原生 ET 分配地址后建立窄子网 VPN 路由，监测实际地址变更并重建接口，不把租用地址保存成静态配置。保留旧版静态二维码兼容与校验；DHCP 参数要求布尔类型，拒绝同时指定静态地址或与电脑子网不符的分配结果。手机 ET 设置新增 DHCP 开关，避免再次保存时丢失导入模式。

扫码配对由应用级协调器管理，经用户确认的待处理请求加密保存，Activity 重建不会丢失进度。组网就绪后限时等待电脑，保留证书固定；配对 POST 不自动重放，未确认结果需重新扫码。进度移到首次连接页顶部，成功后进入聊天。开屏使用约 1.35 秒原生 Canvas 光晕、粒子及代码图形；关闭系统动画时跳过，页面旋转及相机/VPN 返回不重复播放。

39 项 Android JVM 测试、16 项桌面测试通过，五个 Windows PowerShell 发布脚本解析零错误。真机确认 DHCP 开关开启、虚拟接口显示 DHCP 及有效路由，并已进入聊天；电脑新版内置服务运行，真实 DHCP 二维码导出成功。未人为制造重复地址测试冲突迁移。用户确认此前无法连接是手填手机 IP 与另一设备冲突。外部 easytier 服务保持停止；测试二维码已从本机及手机删除，手机熄屏时间恢复一分钟。

发布包不包含个人网络默认名：新安装网络名称为空，覆盖安装加载本机已有配置。界面明确说明这一来源，不自动把 Windows 用户名、主机名作为网络名，也不为了发布而修改用户现有组网身份。

推送前全量桌面及网关 56 项测试通过，Android 39 项测试通过；源码与解包后的安卓、桌面安装包共 174 个文件完成已知本机敏感值扫描，未命中。打包脚本新增本机配置及凭据路径拦截，避免后续残留文件被打包。

## 第二十四轮：随 Codex 插件初始化恢复后台

电脑插件更新为 0.4.14-preview，Android 保持 0.4.13。现场自动启动开关已开启，但旧 MCP 只在 tools/call 时创建后台；重启 Codex 加载插件并不会触发后台启动。现在首次 initialize 即异步读取本机自动启动设置，明确启用时恢复后台，不等待网络启动完成才响应 MCP 握手。关闭开关、没有配置或非布尔启用值均不启动。并发初始化与设置调用复用同一启动检查，已有后台继续复用，探测超时缩短到 1.5 秒。

58 项 Node 回归测试通过，新增自动恢复开关、并发入口合并、仅 initialize 无需工具调用、重复初始化不重复启动检查。五个 Windows PowerShell 发布脚本解析通过。已安装版本实测：原后台不可达，仅向 MCP 发送 initialize 后，按当前已有网络配置恢复连接；结束该 MCP 进程后服务存活，再次初始化后台 PID 不变，本机配置摘要不变。没有为测试关闭桌面 Codex，也没有切换到内置 ET 或启动外部 EasyTier；完整桌面 UI 退出及重新打开由用户继续验收。

## 第二十五轮：Windows 独立后台与 MSIX 实际路径

用户重启桌面 Codex 后再次确认服务未运行。现场无手机连接 MCP 进程，旧 manager 元数据指向已退出 PID；这证明上轮手工 initialize 测试不足以覆盖实际插件加载时机。保留 MCP 初始化恢复作为补充，主要后台改由当前用户 Windows 计划任务独立托管，已开启自动恢复时登录自动运行，Codex 退出不再控制后台进程生命周期；关闭并保存时移除后续自启入口，不主动停止当前连接。

电脑插件更新为 0.4.15-preview，Android 不变。任务名称按当前用户和数据目录派生，仅更新带本项目归属标记的同名任务；不使用 Windows 密码，不接管其他服务。普通已有网络任务使用 Limited 权限；明确通过管理员入口允许后才配置 Highest，管理员入口也由任务托管而非短命 Codex 子进程。安装和配置保存同步后台任务，启动入口仍检查 autoStart 布尔开关。多个实例忽略重复启动，失败可有限重试。

实测发现 MSIX 将本机 AppData 数据目录重定向，包外 Windows 任务无法访问原虚拟路径。用 Windows 文件句柄解析数据目录与插件目录的真实磁盘路径，任务继续读取同一份配置，不复制网络身份、不写死包标识。Windows PowerShell 模块路径按系统环境初始化。诊断仅保存预定义阶段、布尔状态和整数错误码；完整输出持久化方案被自动审批拒绝后已撤回，没有保存原生日志或 RPC 输出。

60 项 Node 测试通过，七个发布 PowerShell 脚本在 Windows PowerShell 5.1 解析零错误。对已安装包实测：停止本插件当前已有网络后台，再仅启动 Windows 任务，不调用 MCP，获得新 PID、运行中的远控接口；新进程父级为任务 PowerShell，祖父为 Windows svchost，不是 Codex。任务处于 Running 且具有当前用户登录触发器，旧虚拟路径失败任务已移除。配置与证书身份摘要不变，外部 EasyTier 未启动。没有在活跃聊天中强行关闭整个 Codex 或注销 Windows；用户可继续进行整机登录与桌面重启验收。

## 第二十六轮：顶部双额度圆环与连接状态颜色
