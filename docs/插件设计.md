## 安装和运行形态

电脑侧按一个本地 Codex 插件包分发，可携带本地 MCP 服务、手机连接服务、EasyTier 可执行文件及依赖。插件后台仍然是操作系统进程；打包在插件中不代表消除进程、管理员权限、网卡或防火墙设置。

不要求另开一个独立电脑客户端窗口。由插件提供“打开连接设置”“查询连接状态”等工具，启动本地配置页面和后台服务。

首版以手动安装的本地插件为目标。官方对目录发布的本地 MCP 插件有额外资格要求，含 hooks 的插件目前不适用于公开目录提交，不能把本地可安装等同于已经可上架。

## 连接模式

| 选择 | 运行行为 | 可配置内容 |
| --- | --- | --- |
| 使用已有网络 / 自建异地组网 | 用户自行完成组网，插件只在指定本机地址提供远控服务；兼容已有 EasyTier 或其他可达 IP 网络 | 本机可达 IP、远控服务端口、连接检测、手机连接地址/二维码 |
| 使用插件内置 EasyTier | 启动插件管理的固定版本 core，使用自己的配置和数据目录 | 网络名称、密钥、对等节点地址、DHCP/静态虚拟地址、监听端口、虚拟网卡名、重连策略 |

已有网络模式不要求安装或检测 EasyTier，不要求填写 CLI 路径、RPC 端口、组网名称或密钥，不接管现有组网程序。用户在插件端填写这台电脑已有的局域网/虚拟网卡 IP；插件校验该地址属于本机，供远控服务绑定并生成连接信息。Android 端填写或扫码取得电脑的 IP 和远控端口，端口可预填默认值。远端组网节点/中继 IP 不能误作本机监听地址。普通局域网直连也使用此模式。

内置模式使用 `easytier-core` 和 `easytier-cli` 作为独立可替换程序，不必把整个 EasyTier GUI 再嵌入一遍。固定版本，附带对应发行版的许可证与源码信息；官方当前主分支 LICENSE 是 LGPL-3.0，实际分发按所选版本核对，不能沿用旧介绍里的 Apache-2.0 假设。

首次创建或管理 Windows 虚拟网卡可能需要管理员权限；插件不自行提权或绕过系统确认。若采用后台服务，安装一次的服务辅助程序和常规配置界面分离，不让整个 Codex 以管理员身份常驻。

## 配置入口

入口名称：**手机连接**，内含“已有网络”和“内置 EasyTier”两种模式。

通过插件工具打开 `127.0.0.1` 的本地设置页面，可在 Codex 浏览器面板或系统浏览器中显示。这里是随插件分发、由插件管理的界面；不承诺能向 Codex 原生设置菜单随意增加页面。

配置页面包括：

1. **连接概览**：服务运行状态、连接模式、连接地址、手机在线状态、桌面接口能力；仅内置模式显示受管 EasyTier 的版本及运行状态。
2. **连接方式**：已有网络/内置 EasyTier 二选一，各自保留独立配置。
3. **已有网络**：本机 IP 输入或从网卡地址选择、远控服务端口、地址校验、连接信息和配对二维码；无需组网软件管理参数。
4. **内置模式**：网络参数表单、配置文件导入、参数校验、保存、启动/停止/重连、经过脱敏的日志。
5. **手机配对**：独立于 EasyTier 网络密钥的设备身份、短期配对码、授权设备列表与撤销入口。配对码不直接携带组网共享密钥。
6. **服务设置**：手机连接地址/端口、允许访问的项目、配置存储位置、跟随 Codex 运行或可选常驻模式。
7. **能力说明**：分别报告读取、实时订阅、任务操作、审批和项目进程管理状态。明确区分“打断对话”和“停止项目进程”，不能用轮次已中断推断子进程已退出。

配置数据存入插件可写数据目录，程序文件留在插件安装目录。网络密钥用 Windows 凭据存储或 DPAPI 等系统能力保存，普通配置只记录密钥引用，表单不会通过读取配置接口返回明文密钥。

## 模式切换

- 已有网络模式只管理本插件远控服务的监听配置，不修改现有组网程序、系统服务或路由。
- 内置实例只由自己的进程句柄/服务身份管理，不按程序名批量结束 EasyTier。
- 内置 EasyTier 启动前检查已有端口、虚拟网卡、虚拟地址和路由。冲突时提示改用已有网络或调整内置配置，不自动停止已有组网程序。
- 通过检查后再切换手机连接服务的绑定地址。失败时保留原有可用配置并显示具体错误。
- 切回已有网络模式时，只停止由插件自己启动的内置实例。

## 网络和会话边界

已有网络模式下，Android 使用手机已建立的网络直接访问电脑远控地址。内置模式下，Android 原生 App 可以接入 EasyTier Android JNI/VpnService，组网后访问同一个远控服务。两种模式共享配对和会话协议；MCP 是 Codex 调用插件管理能力的接口，手机不直接暴露或调用所有 MCP 管理工具。

手机控制入口与本机配置入口采用不同权限。EasyTier 网络成员身份不等于拥有电脑项目执行权限。原生 app-server 保持本机访问，认证、设备授权和移动端事件转发由连接服务处理。

电脑连接服务优先通过已实测的现有 `codex-ipc` 管道访问当前聊天持有者。当前适配器默认只读，写操作需要明确的聊天范围；内部协议不是官方稳定 SDK，分发时需要明确兼容范围，并在桌面升级后重新检查。插件 MCP 服务负责设置、状态和启动管理，手机任务由连接服务按受控操作逐项转发。

EasyTier 改变手机到电脑的传输路径，不改变 Codex 模型服务的运行位置，也不能仅凭插件打包保证官方聊天状态已经可双向控制。

## 在宣称“同一聊天控制”前必须完成的验收

1. 用支持的方式接入桌面实际持有聊天的同一个运行实例，而非启动第二个 writer。
2. 手机提交任务后，桌面同一聊天出现用户输入和回答，重开桌面后仍保持同一聊天 ID。
3. 两端都看到实时输出；断线后能够补取期间的事件/历史，并去重。
4. 忙碌时正确追加/排队/打断，不能并发写坏同一聊天。
5. 两端显示同一审批请求；任一端答复后另一端及时失效，拒绝不能被重复接受。
6. 保持项目目录、模型、插件、工具权限和桌面运行上下文，不能在不提示的情况下切换到另一种执行环境。

## Android 界面与通知目标

目标：核心页面、交互顺序和信息呈现尽量接近官方移动端体验，使用自己的原生 Android 实现；不承诺所有官方能力或布局完全一致。Android 已实现聊天、切换、缓存、内置组网、完成和审批通知，以下仍包含未完成的设计要求。

- 页面：电脑/项目与聊天列表、流式对话、Markdown/代码块、工具活动、命令输出、文件变更与差异、审批卡片、输入与队列、连接/EasyTier 设置。逐项依据接口能力开放；附件、模型设置等尚未端到端验证的操作单独验收。
- 通知：命令/文件审批提供当前请求实际允许的单次操作；任务完成提供结果摘要与快捷回复；运行中显示状态并可打断对话；断线显示连接状态和重连入口。点击通知正文进入对应聊天或审批详情。
- Android 标准通知最多三个操作按钮，可使用 RemoteInput 输入文本。多题、多选、大段命令和文件差异进入 App 展示完整上下文；用户提问协议尚未完整实测，不能与已验证的命令/文件审批混称为全部通过。
- 按钮来自当前请求提供的选项，不能固定假设有“拒绝”或“始终允许”。例如请求仅提供 accept/cancel 时显示“允许一次/取消”。审批摘要明确电脑、项目、命令或文件范围。
- 操作绑定设备、聊天、轮次及请求 ID；点击时由电脑端复核仍有效。桌面处理后撤销手机按钮；请求失效、重复点击、并发应答、断线后点击都需要专门验收。无服务端确认不显示操作成功，离线审批不延后自动执行。
- 通知渠道分为待处理、完成/失败和连接状态；流式正文更新节流，不逐个 token 响铃。提供锁屏隐藏详情与审批解锁策略。
- Android 13+ 需要通知权限。纯局域网/EasyTier 方案要实测息屏、Doze、厂商省电和被终止后的行为；常驻连接不能等同于保证通知实时到达。断线重连后重新获取待处理状态并撤销过期通知。
- “打断对话”按已验证接口实现；“停止项目进程”因实测未通过，暂不提供可用按钮，不将轮次中断显示为进程已停止。

依据：[Android 通知操作与直接回复](https://developer.android.com/develop/ui/compose/notifications/create-notification)、[通知权限](https://developer.android.com/develop/ui/compose/notifications/notification-permission)、[Doze 与后台限制](https://developer.android.com/training/monitoring-device-state/doze-standby)。

## Android 插件/工具同步与设备发现

以下为设计目标，尚未完成手机端或网络端验收。

插件/工具页面按电脑及项目/聊天上下文展示插件名称、图标、说明、安装/启用状态、Skills、MCP 工具名称与说明，以及可获得的连接/认证状态。当前桌面版本生成的协议包含 `plugin/installed`、`plugin/read`、`skills/list`、`mcpServerStatus/list`；这证明存在对应协议结构，不代表当前管道适配器已接入桌面运行实例的这些查询。不能用另起 app-server 的状态冒充桌面聊天的实际工具状态。安装、启用、连接、当前聊天可用四种状态分别显示，未知状态明确标记。

官方当前文档将 `plugin/list`、`plugin/read` 等列为开发中，并明确要求暂不用于生产客户端；插件清单同步只能先做版本受限的验证，发布时应使用届时受支持的查询路径或降级显示。MCP 状态查询支持按 threadId 复用聊天连接，但仍需解决本项目访问同一桌面运行实例的接入问题。

用户在手机选择插件/技能后，通过桌面聊天提交支持的引用或任务，由桌面 Codex 使用其工具和权限执行；不把所有 MCP 工具公开为任意远程调用 API。工具调用过程和结果显示在聊天活动中。专用插件网页、OAuth 和系统界面逐项适配；列表同步不等于所有插件界面可原样嵌入手机，也不自动包含远程安装/卸载功能。

设备发现设计：

1. 同一物理局域网：电脑连接服务公布 DNS-SD/mDNS 服务，Android 使用 NsdManager 发现和解析地址/端口；发现后做实际服务握手和协议兼容检查。
2. 自建异地组网：已有网络模式以用户输入/扫码的电脑地址和已配对设备重连为基础，不要求查询外部组网软件的节点列表。内置 EasyTier 模式可另行验证从受管实例取得候选节点地址并探测远控服务。不能假定虚拟网络转发 mDNS，也不能把组网节点在线等同于远控服务可用。
3. 发现失败时保留扫码/手动地址，处理访客 Wi-Fi 隔离、多网卡、防火墙及地址变化。同一设备经 LAN/EasyTier 出现时按持久设备身份去重，已配对设备优先自动重连。
4. 未配对只公布设备别名、协议版本、服务端口及配对状态等最小发现信息；项目、聊天和插件清单配对后获取。发现广播不作为可信身份，首次连接扫码/配对码校验，后续校验已绑定设备密钥。
5. 设备卡片分别显示发现、可达、待配对、已连接、Codex 未就绪、版本不兼容等状态，只有认证握手和能力检查通过才显示可控制。

依据：[Android NSD](https://developer.android.com/develop/connectivity/wifi/use-nsd)、[Codex App Server](https://learn.chatgpt.com/docs/app-server)。
