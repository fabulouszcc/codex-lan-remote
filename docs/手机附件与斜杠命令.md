# 手机附件发送与斜杠命令

修复 #1、#8。手机输入框左下角增加文件入口，复用系统文件选择器。每条消息最多 8 个附件，每个 32MiB；选择阶段只存 URI 和元数据，点击发送时分块上传。支持现有文件阅读器允许的文本、图片和常见文档格式；密钥、凭据名称和不支持的扩展名会被拒绝。

上传是独立二进制请求，不挤入原有 64KiB JSON 控制请求。随机附件 ID 绑定已配对设备和授权可写聊天；命令忽略客户端伪造的电脑路径。文件保存到 CodexHome/attachments，每个上传独立目录。中断或持久化失败清理不完整文件；成功文件保留，避免破坏聊天和排队消息。移除草稿不会删除已有聊天中的文件。

原生桌面格式：普通文件进入 Files mentioned header 和 composer fileAttachments；图片同时使用 localImage 原图路径；排队消息保存同样的附件上下文。没有全文件 Base64 或大图解码。桌面队列恢复沿用原生已有的绝对路径 src 形式，未保证恢复时的 composer 图片缩略图；模型原图输入和文件卡片下载已验证。

输入 `/` 查看命令：`/new`、`/model`、`/status`、`/usage`、`/compact`、`/skills`。技能从当前聊天工作目录的真实 `skills/list` 获取；只显示唯一可用名称，不暴露技能路径。`/pr 请求` 等技能消息由服务器解析为已安装技能的原生 typed skill 输入，并保存精确恢复链接。客户端不能传任意技能路径。技能消息支持空闲发送或立即插话，暂不支持排队。

`/compact` 显示确认窗口后，调用实际会话 owner 的 compact follower 协议；执行中的任务和只读聊天会被拒绝。没有开放通用 RPC 或重新 resume 已有桌面聊天。

## 验证

- 独立上游基线构建 Android APK，73 项 JVM 测试；电脑端测试覆盖流上传、越界/中断清理、凭据和跨聊天保护、伪造路径、原生 start/steer/queue 格式、技能路径解析、compact 的 owner/空闲/只读限制。
- Android 16 实机：实际 SAF 文件选择后，用户确认输入框显示附件；旋转重建后附件仍在，可移除。实际命令列表、`/pr` 选择、`/status` 状态窗口通过。
- Android 原上传代码通过临时 USB 转发连接带配对指纹的 HTTPS 网关，上传合成文本和绿色 PNG。一个真实原生技能任务读出了文件中的随机标记并识别绿色；两张附件卡片均可下载。测试聊天已归档，选择恢复，USB 转发和手机临时文件清理。该项证明 Android API/网关/桌面模型链路，不单独证明无线文件上传速度。
- 未在现有用户聊天执行实际压缩；compact 覆盖为安装版静态协议核对与自动化 owner 边界测试。未覆盖所有第三方文件提供程序或所有 Android 版本。

## 数据与兼容

无历史格式迁移，不卸载或清空 App，不替换配对和证书，不新增运行时依赖。手机附件和技能功能需配套更新电脑插件，旧插件会明确报错。此 PR 独立基于 main，可单独构建；与其他已开的手机修复 PR 同时合并时，MainActivity 和输入适配器附近可能需要处理文本冲突。
