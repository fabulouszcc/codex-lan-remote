## 结论

**本机桌面会话的主要控制流程已经实测通过，但不能把“打断会话”当成“终止底层进程”。**

12 项会话、审批、状态和持久化核对通过；额外两项“前台/后台命令随打断而停止”的检查未通过。测试共保留 12 个轮次，其中包含初始化、正常任务和有意打断/取消的轮次。当前没有待处理审批。

这证明可以通过已有桌面的协调管道向真实模型提交任务、继续同一聊天、排队、追加指令和处理审批。它尚未证明 Android App、EasyTier 传输、安装插件或长期兼容已经完成。

## 打断的明确边界

两次测试都执行无文件写入、无网络访问的 25 秒 PowerShell 等待命令。打断请求成功返回，桌面停止继续生成，并将轮次标为 `interrupted`。

但后来收到的真实工具结果显示：

- 后台测试：命令持续 `25129ms`，退出码 `0`，输出 `LAN_TEST_SHOULD_NOT_FINISH`。
- 前台测试：命令持续 `25153ms`，退出码 `0`，输出 `LAN_TEST_FOREGROUND_SHOULD_NOT_FINISH`。

所以当前实现可以提供“打断 Codex 本轮对话”，**尚不能提供保证有效的“停止项目/终止执行进程”按钮**。该结论仅针对本机版本和测试的执行链路，不推断所有 Codex 版本、工具或子进程的行为。

若要支持项目进程停止，需要额外的受控进程管理：准确识别本系统启动的进程或执行会话、请求终止并等待确认、处理进程树、收集退出状态。不能仅凭一个 `interrupted` 标签判定项目进程已退出，也不能按进程名称批量结束用户其他项目。

## 审批处理细节

审批测试仅对专用测试聊天使用按需审批和只读沙箱，测试写入均限定在其 `work` 子目录。没有请求会话级持续许可或保存命令前缀规则。

实际命令审批提供的是 `accept`、可选前缀授权和 `cancel`，本轮仅使用单次 `accept` 与 `cancel`。取消会同时中断该轮，不能把它描述为“拒绝命令后模型仍继续运行”。

文件审批本身只返回 itemId，变更详情来自对应的实时 `fileChange` 项。审批 UI 必须关联这两个来源，以便展示真实路径、补丁和状态。

测试客户端会拒绝不在当前 requests 中的旧 requestId。真正两台设备同时处理同一审批的竞态，以及原生服务对重复决策的处理，仍需要单独联调。

## 本轮实现

- `server/desktop-ipc.mjs`：默认只读；只有构造时明确列入 `controlThreadIds` 的聊天允许写操作。新增提交、steer、打断、队列和单次审批方法。
- `server/thread-state.mjs`：状态快照和增量重建，核对版本连续性，拒绝不安全补丁路径；支持分页 canonical 历史。
- `scripts/control-test-session.mjs`：本机 stdin 测试驱动，无网络监听。仅用于明确授权的专用聊天。
- `scripts/audit-control-test.mjs`：复核真实桌面状态、测试文件和落盘回复，输出 `.local/verification/control-flow-results.local.json`。
- `tests/`：12 项自动化测试通过，覆盖分帧、消息归属、写操作默认关闭、线程范围限制、状态版本及补丁安全。

审计命令：

```powershell
node scripts/audit-control-test.mjs <已授权测试聊天ID>
npm test
```

审计脚本在完整验收未通过时返回退出码 `2`；当前正是因为上述两项进程停止检查未通过。`npm test` 只运行隔离的自动化测试，不向真实模型发送任务。
