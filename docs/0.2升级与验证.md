# 0.2 聊天、缓存和通知修复

## 原因与变更

- 0.1 手机固定取 `threads[0]`，电脑配置也只提供专用测试聊天。0.2 加入本机聊天目录和显式选择接口，手机提供切换入口并记住当前聊天。默认仍只控制配置清单；开发机按用户的对话切换请求启用了已配对手机选择控制的模式。
- 0.1 仅保存配对凭据，不保存聊天。0.2 使用 Keystore AES-GCM 加密和 AtomicFile 保存按电脑身份隔离的本地历史；页面先读缓存，再同步电脑。离线不会显示可操作的旧审批。
- 实时快照不等同于完整持久化历史。0.2 首次接入时主动请求桌面持有者加载历史，并通过独立只读 app-server 的 `thread/list` 和 `thread/turns/list` 补取已有记录。历史读取不启动模型、恢复线程或抢占 writer。历史 userMessage 还补充了输入文本解析，避免只有 params.input 才能显示。
- 0.1 未实现任务通知且仅前台同步。0.2 加入 remoteMessaging 前台同步服务、通知权限/渠道入口、完成/失败提醒和审批通知。通知动作绑定聊天、轮次和请求 ID，复杂/不完整差异不提供直接允许按钮。系统强杀、厂商省电及真正息屏送达仍待小米真机验收。
- 电脑端增加脱敏的操作回执 `.local/verification/gateway-actions.local.jsonl`，记录设备名称、聊天、操作、审批选择及结果，不记录提示词、命令正文、密钥或令牌。可区分手机点击审批和仅由手机发起任务。

## 已完成验证

- Node 22 项自动化测试通过：包含初始历史加载、稀疏快照不覆盖旧文本、关闭聊天不阻塞其他聊天、目录与选择的认证边界、跨轮次审批拦截。
- Android 状态层 7 项 JUnit 测试通过：重连空快照保留记录、离线审批清除、已知任务完成与重连通知、快速任务跨轮询完成、历史补取不误报完成、多聊天缓存。
- 真实只读历史读取：首次接入、不发送新消息，即读到专用聊天已有 23 轮，包含 `PHONE_TEST_OK` 和 `BLUE-731`。
- HTTPS 控制回归 12 项通过：基础收发/去重/撤销授权，加上执行中追加同一轮、真实文件审批允许及取消。审批由标记为“本机 HTTPS 联调验证”的脚本客户端处理，不冒称来自手机点击。
- 0.2 APK 完成构建；签名与 0.1 一致，APK 对齐校验通过。手机实际页面、覆盖升级后的缓存和通知弹出尚未验收。

构建时规避了本机 PATH 含字面引号、Gradle worker 非 ASCII 参数文件和工作区生成文件重解析点问题。脚本先编译 Android/JVM 测试再直接运行 JUnit；没有跳过测试。开发 APK 使用可重复的本地调试签名。

## 升级后优先复测

1. 覆盖安装 0.2，先打开已有测试聊天；无需发消息，应立即看到电脑历史。
2. 选择另一个聊天，再切回；核对标题和记录不串线。未在桌面加载的聊天先只读历史。
3. 等同步完成后断网并重开 App；确认仍可查看已缓存的最近记录，发送/审批被禁用。
4. 连网运行一个延时任务后返回手机桌面，确认完成通知及点击定位。
5. 发起真实审批后退到后台，确认审批通知；点击一次允许或取消，查看电脑回执确认来源。

旧版本未保存到手机的数据不能凭空恢复，但升级联网后会主动从电脑补取并开始缓存。当前缓存保留最近记录，不能承诺已经完整下载整个电脑历史。
