# Android 大历史记录内存回归

大历史记录断线或重新进入时，`MobileState.offline` 的 JSON 深复制、行签名保存的整段 JSON，以及缓存序列化的字符串/字节数组会同时保留多份正文。真机崩溃记录曾在离线转换与缓存保存路径出现 OOM；仅扩大堆或裁剪聊天不能解决这些副本。

本次改动复用现有 `copyFields`、`AtomicFile` 和 AndroidKeyStore：

- 离线状态只复制根对象和需要清除安全状态的聊天对象，保留原始正文与轮次，且不改动源对象。
- 行签名改为定长 SHA-256；JSON 写入和摘要按片段流式处理。
- 缓存使用 `CLH2` 分块 AES-GCM，每块最多 64 KiB，随机 IV 由加密提供程序生成，兼容要求随机加密的 AndroidKeyStore。块序号、明文长度和格式标识受 AAD 认证，末尾的认证空块用于检测截断及尾随数据。
- 保留旧缓存读取，在首次转换前原子保存 `.legacy.bak`。显式清除缓存时也删除该备份。新格式只消除全量序列化/加密缓冲，仍需保留完整解析后的聊天对象；旧格式首次读取仍使用旧的整份密文解密路径。
- Activity 与 Service 在进程内共享软引用缓存，避免启动时重复解析；服务初始化移到工作线程。常规全量保存间隔从 2 秒改为 10 秒，告警变化仍立即保存。进程突然终止时，最近的非告警更新可能尚未写入离线缓存，联网后可重新同步。

## 兼容与回退

不改变包名、版本号、配对密钥别名、网络配置或聊天数量。旧版无法读取 `CLH2`；回退时可使用保留的旧格式备份，但它只代表首次转换前的状态，不包含之后的新缓存更新。此改动没有迁移或删除电脑端聊天记录。分块加密增加了提供程序调用次数，首次大缓存转换耗时不能等同于普通同步耗时。

## 验证

`MobileStateTest` 增加四项回归：禁止全量状态/行 JSON 序列化，源数据不变且轮次正文共享，签名定长且能识别变化，写入转义和 Unicode 保真，对象键顺序不影响摘要但数组顺序会影响摘要。保持现有 JVM 测试入口不变。

真机测试使用独立的临时 AndroidKeyStore 别名、合成聊天和本次运行专属缓存目录，不访问配对或真实历史。需要一个已安装的可调试版本与 Android 16 ARM64 手机，通过 USB 授权 ADB。以 PowerShell 运行：

```powershell
./scripts/test-android-memory.ps1 -SdkPath <Android-SDK> -JavaPath <JDK-17> -Adb <adb.exe>
```

SDK 需安装 platform 35 和 build-tools 35.0.0。脚本编译当前源文件，使用真实 AndroidKeyStore 完成约 25 MiB / 50 轮数据往返及完整摘要比较，校验篡改、截断拒绝，验证写入失败保留原文件、旧缓存备份保真及清除行为。退出时删除测试密钥和本次测试缓存；不停止 App、不安装 APK。

本地证据：原序列化路径下，76 项 JVM 测试中新增的两项失败；修复后 76 项在 `-Xmx96m` 下全绿，`assembleDebug` 成功；上面的独立真机脚本通过全部数据、认证、回退、备份与清除断言。修复版还在真实设备上完成记录与配对保留、重新打开及同步恢复检查。这些证据不等于长期稳定性保证，仍需覆盖不同 Android 版本、设备和更大数据量。
