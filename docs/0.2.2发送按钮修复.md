# 0.2.2 发送操作修复

用户反馈：连接正常但点击发送没有效果。操作回执还发现手机追加和打断被拒绝；回执没有记录错误正文，无法仅凭这些记录确定手机当时的实时状态。

发现并修正的代码问题：

- 旧界面会因任一历史轮次标为执行中而禁用发送，没有解释原因。现在网关单独发布来自实时桌面状态的 `activeTurnId`，手机不使用旧缓存判断当前活动任务。兼容旧网关时仅检查最后一轮。离线记录不能产生可操作任务。
- 当前任务执行中，主按钮显示“发送追加”，使用已有 steer 操作追加到当前任务；不自动重试或另发新轮次。空消息、离线、只读和聊天未就绪均给出具体提示。
- 状态提示可点击重新同步，主动重取所选聊天和历史，不启动模型任务。

验证：Node 23 项、Android JVM 10 项通过，含旧历史执行中但实时桌面空闲、旧网关兼容和不可操作原因的回归。APK 构建成功。网关重启后，通过证书校验的 HTTPS 只读检查确认当前聊天 ready/writable 为 true、实时活动轮次字段存在。没有发送模型测试消息。手机实际点击仍需覆盖安装后确认。

版本 `0.2.2-preview`，versionCode 4，沿用本地签名，保留配对和 EasyTier 配置。更新后重新打开 App 并连接 EasyTier；显示未就绪时点击发送按钮下方状态文字重新同步。
