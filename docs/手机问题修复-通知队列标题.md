# 手机通知、队列与自动标题修复

对应 #4、#5、#6。APK 和电脑插件均需更新；协议只增加字段，旧版忽略未知字段。未改变包名、配对、证书或已有聊天内容。

## 行为

- 原生和异步问题加入“等待回复与电脑权限请求”高重要性通知频道，点击打开对应聊天；提交、解决或离线后取消过期通知，重复同步去重。
- `item/permissions/requestApproval`、`mcpServer/elicitation/request`（包括浏览器访问授权）和 `item/tool/requestOptionPicker` 显示只读提醒。它们不等同命令/文件的 accept/decline，手机不伪造授权按钮；仍需在电脑处理。消息正文/权限原始参数不放入此类提醒。
- 同时读取桌面服务器队列 `thread/queue/list` 与旧 sidebar 队列，分页并按 clientUserMessageId 去重，保留服务器条目的 id。旧广播不清掉服务器条目，10 秒补充刷新有 epoch 保护；移除交给现有 owner IPC。服务器队列绝不写回旧的 local setter，以免重复执行消息。
- 手机新建未指定标题的聊天记录一个待自动命名标记，首轮完成后通过临时只读模型生成短标题，再重新核对真实标题仍为预期占位名才写回。手动标题与非该流程创建的聊天不自动改名。目录也更新为桌面的最新名称。
- 标题模型优先使用可用的 gpt-6-luna，回退到可用低推理模型。独立临时会话禁用工具、MCP、插件等，不 resume 用户会话。生成结果和待处理标记保存在本机 `auto-titles.local.json`，不保存聊天正文。每个标记只尝试一次模型请求，失败后不会在每次同步无限重试；若运行实例变化，已生成标题可复用。该功能会产生少量额外模型用量。

## 证据和限制

- 原等待输入测试失败（预期提醒 2 条，实际 0）；新原生权限投影测试也失败。修复后 Node 103 项、Android 75 项通过，APK 构建成功。
- 当前安装的桌面 26.1103 / Codex 0.167 协议已静态核对；真实只读 queue/list 成功，但真实非空服务器队列未人为插入测试消息。非空合并、去重、保序、移除和不重复回写由可复现模拟测试覆盖。
- 用户确认真机收到“等待回复”通知，点击回到正确聊天。
- 模型标题独立实测通过；手机端客户端再通过已配对的固定证书 HTTPS 新建专用聊天、完成合成任务并在 Android 状态接口读到新标题。专用聊天已归档，没有更改用户其他聊天。这是 API 完整链路验证，未自动操作手机新建按钮。
- 真实桌面权限弹窗到手机的整链路没有人为触发，已用当前协议类型与合成快照测试只读投影、无敏感原始参数及过期过滤。
- 原生改名 API 没有 expectedName 原子 CAS。实现生成前后检查真实标题并使用运行实例 guard，但不能完全消除另一客户端恰好在检查与写入之间改名的竞态。
- 该适配依赖桌面内部协议，后续桌面更新可能需要兼容调整。
